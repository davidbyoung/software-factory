# Design

- **A cloud run** replaces `session.yml`'s one job with three, in the same file, called by `run.yml`'s jobs. `factory session prepare`, `factory session run` (which writes the agent's settings and starts it), and `factory session publish` are new files, `src/session-prepare.mts`, `src/session-run.mts`, and `src/session-publish.mts`, registered in `src/session.mts`. `src/session-token.mts` signs Prepare and Publish in, and no session.
- **What a session reads and writes** is a second implementation of `CodeHost`, `Tickets`, and `Runner`, in `src/handoff/`, which `openCodeHost`, `openTickets`, and `openRunner` return when `FACTORY_HANDOFF` names a folder. Reads come from `snapshot.json`, written by Prepare through the real adapters; each write appends to `request.json`. A method with nothing recorded throws the "was not handed" error, so no read answers empty.
- **The sandbox's settings** are the agent's: `src/agent/claude-code-session.mts`, since another agent confines its commands its own way.
- **The review** moves from `review.yml` to a job of `run.yml` on `pull_request_target`, and its threads and status are posted by Publish. `anthropics/claude-code-action` goes. `.github/factory-review.md` says what to report, not how to post it.
- **`FACTORY_HANDOFF`** names a folder with `in/` (`run.json`, `snapshot.json`, `work.bundle`, `home.bundle`, `presets/`) and `out/` (`request.json`, `build.bundle`). `run.json` has `kind`, `repository`, `defaultBranch`, `base`, `branch`, `ticket`, `pull`, and `round`. `request.json` is `{"version": 1, "commands": [{"argv": [...], "files": {...}}]}`: each is a `factory` command, run by Publish when it is on a fixed list, with the ticket or pull request of this run.
- **The sandbox**, from the live tests: `sandbox.enabled`, `failIfUnavailable`, `allowUnsandboxedCommands: false`, `network.allowedDomains`, `credentials.envVars` with `deny`, `filesystem.allowWrite`, and `denyWrite` for what was handed over, since a folder named to the session with `--add-dir` is writable; `permissions.deny` for `/proc` and `/sys`; `disableAllHooks`; passed with `--settings`, and `--setting-sources project`. On Ubuntu runners the distribution's own `bwrap` AppArmor profile is replaced by the documented one first.
- **A marker of the factory's** is any HTML comment, taken out of what a session wrote except the one the request itself is for.
- **The next run** is a `workflow_dispatch` of `factory.yml` with today's inputs, made with the App's token or the person's, since the workflow's own starts nothing.
- **Limits:** Prepare 15 minutes; the session's as `session-minutes` says, plus 10; Publish 75, waiting for CI up to 60, then it comments that CI has not finished and leaves the pull request a draft.
- **An App that is not installed** is told by `runToken` in `src/code-host/github-app.mts`, which Prepare and Publish sign in through, in place of `actions/create-github-app-token`.
- **The review's job** is in `run.yml`, which `factory.yml` calls. `factory-review.yml` keeps "Factory files in step" alone.
